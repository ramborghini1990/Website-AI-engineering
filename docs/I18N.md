# I18N.md — internationalisation with next-intl

Decision D4: Italian is the default locale; English is a full translation adapted for the market, not a literal one (CLAUDE.md §12). Every user-facing string goes through messages; the Italian text is authoritative for legal pages.

## How it fits together

| Piece | File | Notes |
|---|---|---|
| Locales and routing | `src/i18n/routing.ts` | `it` (default) and `en`; prefix always (`/it`, `/en`) |
| Redirect `/` → locale | `src/proxy.ts` | Next 16 name for `middleware.ts`; picks the locale from `Accept-Language`, falls back to `it`; skips `/api`, `/_next`, `/_vercel` and any path with a dot (static files, `/.well-known/...`) |
| Locale at request time | `src/i18n/request.ts` | reads the `[locale]` root parameter via `next/root-params`; loads `messages/<locale>.json`; unknown locale → 404 |
| Typed keys | `src/i18n/messages.ts`, `src/i18n/next-intl.d.ts` | `it.json` defines the shape; a key used in code but absent from it is a **type error** |
| Navigation helpers | `src/i18n/navigation.ts` | `Link` and `usePathname` that add or strip the locale prefix; use these, not `next/link`. `redirect`, `useRouter` and `getPathname` are available from `createNavigation`; export them when first needed |
| Root layout | `src/app/[locale]/layout.tsx` | there is no `app/layout.tsx`; this layout owns `<html lang>`, fonts and the provider |
| Messages | `messages/it.json`, `messages/en.json` | identical keys and placeholders (tested) |
| Language switcher | `src/components/language-switcher.tsx` | links to the same path in each locale |
| hreflang and canonical | `src/lib/seo.ts` (`localeAlternates`) | from page metadata, absolute via `metadataBase` = `siteUrl` (`src/lib/env.ts`) |

## Rules

- **No hard-coded copy in components.** Components that need a string take it as a prop (see `closeLabel` on Dialog) or call `useTranslations`.
- **Add a key**: add it to `messages/it.json` first, then `messages/en.json` with the same shape. `pnpm typecheck` and `pnpm test` fail if they differ, or if code uses a key that is not in `it.json`.
- **Client components** only receive the namespaces the layout passes to `NextIntlClientProvider` (currently `languageSwitcher`). Add a namespace there when a client component needs one.
- **Page titles**: a layout's `title.template` applies to *child* segments only. Home and the 404 set `title: { absolute: "... | <brand name>" (the brand token from `src/lib/business.ts`) }` themselves; pages in child segments just return `title: "..."`.
- **Every page** exports `generateMetadata` with `alternates: localeAlternates(locale, pathname)` (pathname without the locale prefix).
- **Not-found**: unknown paths under a valid locale hit `[locale]/[...rest]/page.tsx`, which calls `notFound()`. A nested `not-found.tsx` cannot set `<title>`; the catch-all route does.
- **Route Handlers and Server Actions** cannot use `next/root-params` yet: pass the locale explicitly (`getTranslations({ locale, namespace })`).
- Dates, numbers and currency go through `useFormatter` / `getFormatter`, never `toLocaleString` with a hard-coded locale.

## Privacy

There is **no locale cookie** (`localeCookie: false`): the URL carries the choice and nothing is stored about the visitor. `Accept-Language` is read to redirect `/` and is not logged or stored. If a persistent preference is ever added, list the cookie in the cookie policy (P4.2) first.

## Adding a locale

1. `src/i18n/routing.ts`: add it to `locales`.
2. `messages/<locale>.json` with the same shape as `it.json`; add a loader in `src/i18n/request.ts` (the `satisfies Record<Locale, ...>` forces this).
3. Add the language name to `languageSwitcher.names` in **every** message file (each in its own language).
4. `pnpm verify` and `pnpm test:e2e`; extend `e2e/i18n.spec.ts` with the new locale.
