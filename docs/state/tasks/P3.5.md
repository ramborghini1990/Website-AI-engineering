# P3.5 — task report

Demo analytics and funnel attribution, cookieless and aggregate. Read only when working on or near P3.5. Design and limits: `docs/ANALYTICS.md`; decision D37.

- **Decisions for you.** (1) **No Plausible.** The ROADMAP says "dashboard in Plausible"; that needs a third-party script (against "no third-party script without consent") and a new processor. I built first-party counters instead (D37) and the funnel is read with SQL. Say if you still want Plausible (then: consent gate or server-side forwarding, and the CSP origin that already exists). (2) **Definition of "completed"** per demo (approved one action / scheduled one message / asked one question / rang one sale or received one order): mine, product call. (3) **Do Not Track / GPC send nothing**, stricter than the law needs for aggregates. (4) Disclose in the privacy notice (P4.2) and ROPA (P4.3); needs legal review.
- **Behaviour.** `demo_started` = first click inside the demo (once per page view); `demo_completed` once, and it also reports a missed start; `cta_clicked` every click. Page view alone sends nothing. Browser → `POST /api/demo-events` `{ event, demo }`; server: same-origin → JSON/≤256 B → strict Zod → rate limit (salted IP hash, in-process 30/min) → `count = count + 1` in `demo_event_counts` (migration 0002). Over-limit = silent 204.
- **Defects found (mine, fixed).** (a) First version imported the Zod schema into the browser bundle: the enforced CSP reported `script-src <- eval` and 4 existing demo specs went red; schema moved to server-only `event-schema.ts`, with a structure test banning Zod/server imports in the client files. (b) A 429 for the rate limit would have put console errors in busy pages (and made e2e flaky: all tests share one IP); now 204. (c) New CTA locator matched header and footer links too (scoped to the demo section).
- **Existing tests changed.** The four "nothing leaves the page" demo specs (instagram, linkedin, docintel ×2, business) now let through exactly one request, a same-origin `POST /api/demo-events` whose body is exactly `{ event, demo }` (`e2e/support/analytics.ts`); every other non-GET, `/api` or foreign request still fails them. `vitest.setup.ts` stubs `fetch` in the jsdom environment so no unit test can reach a network.
- **Measured.** Gate: unit 1557 (+46), e2e 651 (+12). Unit (schema, record, limiter, origin, counters, funnel, migration↔schema, route, client hook, structure). E2E (production build, enforced CSP): per demo nothing on page view, one `demo_started` on first click, no cookie, no localStorage; CTA reports `cta_clicked` and still lands on `/contact?service=ai-agents`; a sale reports started then completed; DNT sends nothing; no script from a third party; endpoint 204 / 400 (extra field, unknown demo or event) / 403 (foreign origin) / 405 (GET).
- **Not measured.** The Drizzle upsert against a real Postgres (only a fake and the SQL↔schema check; no database exists, B13); behaviour on Vercel (header names `x-forwarded-host`, `x-real-ip`); keepalive delivery when the page unloads (CTA click) in Firefox/WebKit; Lighthouse; the SQL in `ANALYTICS.md` was not run.
