# P4.3 — task report

Data subject rights and retention. Decision D40.

- **Built.** `src/lib/privacy/`: `retention.ts` (730 days default, bounds 30–3650, cutoff maths), `store.ts` (find/delete by email, delete before a date; Drizzle + in-memory; only `inquiries`), `dsr.ts` (`export`/`delete` logic, injected store and file writer), `cron.ts` (bearer check, purge, counts only), `runtime.ts` (env → deps). `scripts/privacy/dsr.mjs` (plain Node 24, loads the TS natively) behind `pnpm dsr:export` / `pnpm dsr:delete`. Route `GET /api/cron/purge-expired`; `vercel.json` cron `17 3 * * *`. Env: `CRON_SECRET` (≥32 chars), `INQUIRY_RETENTION_DAYS` (default 730).
- **Receipts are untouched by construction.** No privacy file names the receipts table (a test reads the code, comments stripped, with a negative control); every store statement is asserted to target `inquiries`. Receipts hold no identifier, so an export cannot include them: the export says so.
- **Safety choices.** `delete` is a dry run without `--confirm`. The tool prints the DB host (no credentials) before acting, never reads an env file, writes `--out` as a new file with mode 0600. stderr has counts only; a DB error is shown by class only (Drizzle errors quote the query parameters, i.e. the address). Retention outside 30–3650 throws, so a typo cannot wipe the table. Cron: unset secret → 503, wrong header → 401, constant-time compare.
- **Docs.** `docs/DSR.md` (30-day SLA, extension rule, identity check, per-right procedure, manual steps the tool cannot do, purge), `docs/ROPA.md` (9 activities, processors, gaps), `DEPLOYMENT.md` §3 (cron setup), `GDPR_CHECKLIST.md` (4 items now partly done).
- **Defects/gaps found while building.** (1) Notice says 24 months "from the last contact"; the table has only `created_at`, so the purge runs from the first contact (never later than the notice, but cuts off a long conversation). (2) The marketing-consent proof lives in the inquiry row, so the purge deletes it at 730 days while the notice says "until you withdraw"; harmless today (no list exists), wrong once a newsletter exists. (3) The tool cannot erase the notification emails in the inbox, Resend's log, Cal.com bookings or backups: listed in DSR.md §4 and printed after every run. (4) Receipt retention is undecided and nothing purges receipts.
- **Test premises changed (none weakened).** `legal-structure.test.ts`: `CRON_SECRET`, `INQUIRY_RETENTION_DAYS` added to the reasoned "not a service" list. `env-schema.test.ts`: new cases only. `logger.ts`: new allow-listed field `count`.
- **Config changes outside the task.** `tsconfig.json`: `allowImportingTsExtensions` (the CLI's shared files import each other as `./x.ts` because plain Node has no `@/` alias; it is safe with `noEmit`). `knip.json`: `scripts/privacy/*.mjs` entry.
- **Gate.** First full run: unit failed on one test (`cli.test.ts` default 5 s timeout while four real Node processes started under full-suite load; fixed with a 30 s timeout on that block). Final run: see PROJECT_STATE §5.
- **Measured.** Unit: 59 tests in `src/lib/privacy`, incl. the real command line under Node 24 (usage, bad env, unreachable DB: no password or address on stderr), SQL shape rendered through Drizzle's dialect, cron auth negatives, env bounds. No UI changed, so no visual e2e was added.
- **Not measured.** Any run against a real Postgres (the SQL is checked by rendering, not executed; `lower(email)` has no index, fine at this volume); a real Vercel Cron call (Hobby/Pro limits, bearer header taken from Vercel's docs); Windows PowerShell quoting beyond the documented example; legal accuracy of DSR.md and ROPA.md.
- **Decisions for you.** (1) Reword the notice to "24 months from the request", or add a last-contact column. (2) Pick a retention for receipts and for the request register. (3) Want a `data_events` tombstone table (GDPR_CHECKLIST §6)? Left out: a hash of an address is still personal data, and it needs migration 0004. (4) A DB trigger forbidding update/delete on `consent_receipts` would make "immutable" true in the database, not only in code; needs a migration (B13).
